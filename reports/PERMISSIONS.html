Z Skills — Permission Prompts

An estimate of how many Claude Code permission prompts the user would have faced building Z Skills, if approvals had been live instead of bypassed via --dangerously-skip-permissions.

The headline depends almost entirely on the permissions config. A permissive config gives a few hundred prompts. A conservative one (like the example used here, with gh * and web tools in ask) gives thousands. This page uses EXAMPLE_settings.json — a representative enterprise-leaning Claude Code config — as the reference, applied to the actual JSONL tool-call history.

Methodology

Settings source

Permission rules taken from EXAMPLE_settings.json alongside this report. This represents a conservative enterprise-leaning Claude Code config — the kind that puts gh *, curl *, WebFetch, and WebSearch in ask for visibility-on-network-and-PR-actions. A more permissive config (e.g., moving gh * to allow) would dramatically reduce the count.

Permission model

From Anthropic's permission docs:

  • Rule precedence: deny → ask → allow. First match wins, so an ask rule beats any allow rule and any subsequent "always-allow" click.
  • Bash: "Yes, don't ask again" persists permanently per project per command prefix. First-time prompt; subsequent matching calls auto-allow.
  • Edit/Write: "Yes, don't ask again" persists only until session end. Every new session re-prompts on the first Edit or Write.
  • Built-in read-only Bash: ls, cat, echo, pwd, head, tail, grep, find, wc, which, diff, stat, du, cd, and read-only git subcommands — never prompt regardless of config.
  • Process wrappers: timeout, time, nice, nohup, stdbuf, bare xargs — stripped before pattern matching.
  • Read / Grep / Glob tools: No approval required.
  • Compound commands: Each subcommand checked independently (separators: &&, ||, ;, |, |&, &, newline).

Tool-call extraction

Scanned 2,465 JSONL files across 6 project working directories (~/.claude/projects/-workspaces-zskills/ + 5 -tmp-zskills-*/ worktree-spawned dirs). For each assistant turn, extracted every tool_use content block; recorded tool name and input parameters. Bash commands were classified by deriving the primary command intent (first non-noise word after stripping wrappers and env-var assignments) and matching against the settings' allow / ask / deny lists. The 2026-05-21 snapshot scanned 8 dirs; two -tmp-zskills-* dirs have since been cleaned off disk and their historical traffic is no longer measurable, which understates some net-growth figures relative to pure activity scaling.

Counting model

  • Bash first-time prefixes: Each unique prefix that would have triggered a default-mode prompt is counted once. The prefix is the dialog's most-permissive suggestion (typically first word, or first+second word for multi-subcommand tools like git, npm, gh).
  • Bash every-time: Each call matching an ask rule is counted as one prompt — per Anthropic docs, ask rules prompt on every invocation regardless of prior "always" clicks.
  • Edit/Write: One prompt per session that contained at least one Edit (or Write) call. This assumes the dialog offers a session-wide "allow until end of session" option, which is the most permissive option per the docs.
  • Agent: One prompt per unique subagent_type. Persistence is not documented explicitly; estimate could rise to one-per-type-per-session.
  • WebFetch / WebSearch: Counted as every-call (both are tool-level ask in EXAMPLE).

What this doesn't count

Pre-2026-04-18 development (~23 days, ~1/3 of project elapsed time) has no JSONL transcripts. Prompts during that period are excluded. Additionally, this analysis assumes Claude Code's permission dialog always offers a "most permissive" option (always-allow scope or session-scope); if the dialog only offers single-shot approval for some tools, prompt counts would be substantially higher.

Verification

The 2026-06-01 refresh was double-checked by five independent verification agents using methodology distinct from the primary Python recompute (ripgrep over raw JSONL bytes for Bash/WebFetch/WebSearch counts, grep -l file-list-union/intersection for Edit/Write session counts, separate spot-check sampling for breakdown claims). All agents reported the headline figures match within ~0.05% (methodology noise on total Bash count from JSON-extraction-regex edge cases).

  • Permission docs cross-referenced. Anthropic's permission documentation directly confirms the per-Bash-prefix-permanent / per-session Edit/Write / never-prompt-read-only model used here.
  • Bash ask-pattern counts verified independently. Ripgrep on raw JSONL bytes returned 969 gh * and 126 curl *; primary Python pass matches exactly. WebFetch (104) and WebSearch (72) match exactly.
  • Hard-deny breakdown verified. Independent count using the literal deny patterns from EXAMPLE_settings.json (rm -rf /, rm -rf /*, dd *, sudo *): 210 + 2 + 1 = 213. The 210 figure for the rm-deny pattern reflects commands whose command field starts with rm -rf /... after env-var stripping (anchored, DOTALL on); a verifier using a different anchor (raw substring) reported 422 hits, of which 96% target legitimate /tmp/... paths (the EXAMPLE config's rm -rf /* glob is intentionally broad).
  • Session counts verified. Cross-checked via grep -l '"name":"Edit"' file-list (800 Edit / 661 Write / 1,127 union / 334 intersection). Counts match the primary Python pass exactly.
  • Methodology caveat: unique-prefix count is noisy. The "274 first-time Bash prefixes" includes parsing artifacts — shell keywords (for, until, while, if), shell-syntax fragments (&&, ., {, # comment lines, "$(git quoted heredoc fragments), and lowercase env-var assignments my env-stripper misses (f=/tmp/..., to=/tmp/...). Real distinct commands is closer to 40-50. The 2026-05-21 snapshot's 440 was inflated in the same way; the gap between 440 and 274 is therefore methodology-divergence between parsing passes, not a real shrinkage in the project's command surface.
  • Two project dirs dropped. The 2026-05-21 snapshot scanned 8 dirs (1 main + 7 -tmp-zskills-*); the 2026-06-01 refresh has 6 (1 + 5). Two ephemeral worktree dirs were cleaned off disk between snapshots and their JSONL is no longer measurable. Per-bucket growth rates carry this caveat — some figures are accordingly understated.
  • Settings rules cross-referenced with current file. Allow/ask/deny lists read directly from EXAMPLE_settings.json at the time of analysis.
