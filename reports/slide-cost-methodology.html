Cost Methodology

How the cost figure was computed

From raw session transcripts to a defensible cost estimate. See the full methodology section of the cost report for the dedup logic, API-response semantics, and verification details.

1

Collect

Scan 1,617 JSONL files across 8 project working directories (~/.claude/projects/-workspaces-zskills/ + 7 worktree-spawned dirs). Extract every assistant usage record.

2

Dedup

Group records by message.id — one ID = one API response. For output_tokens (cumulative across streaming records) take the max; other fields are constant per response.

3

Price

Apply Anthropic's published per-MTok rates: Opus 4.7 at $5/$25/$6.25/$10/$0.50; Haiku 4.5 at $1/$5/$1.25/$2/$0.10. No Fast mode, no batch, default global residency.

4

Project

For the 23-day Opus 4.6 era (pre-logging), scale the logged daily rate by commits/day workload ratio (0.633). Range bounded for tokenizer-density uncertainty.

Verification

  • API semantics — Anthropic streaming docs confirm usage is per-response, with cumulative output_tokens across message_delta events.
  • Field consistency — 100% of multi-record message.ids show identical input_tokens / cache_* values (verified across 35k+ multi-record IDs).
  • Cross-file uniqueness — no message.id appears in more than one JSONL.
  • Manual trace — 20 random message.ids inspected by hand; matches dedup logic.
  • End-to-end session walk — a short session counted by eye (5 API responses) matches dedup-by-id (5).
  • Three arithmetic methods — aggregate, per-record, per-day — reproduce the grand total to the cent.
Limits: pre-2026-04-18 era has no JSONL transcripts — its cost is a workload-ratio projection, not a measurement. No external billing oracle (Claude Max subscription has no per-token invoice).
