# Plan: Dashboard Tabs and Rename

> **Landing mode: PR** -- This plan targets PR-based landing. All phases run
> inside a worktree on the feature branch **`feat/dashboard-tabs-rename`**
> (created in Phase 0 via `/create-worktree`). Each phase commits to that
> branch; the orchestrator dispatches `/land-pr` after Phase 4 completes.

## Overview

This is a **presentation-only refactor** of the `/zskills-dashboard` skill
(`skills/zskills-dashboard/`). Two surfaces change:

1. **Rename** "Z Skills Monitor" → "Z Skills Dashboard" across every
   user-facing surface (browser title, H1, SKILL.md echo strings, server.py
   help/log/docstring/fallback HTML, file-header JS comment) AND the test
   assertions that grep those strings.
2. **Tab navigation**. The dashboard at `http://127.0.0.1:<port>/` currently
   crams five panels (Plans, Issues, Branches, Worktrees, Recent Activity)
   onto a single page; the user must scroll through a wall of text to find
   the panel they want. This plan introduces a WCAG-compliant tab pattern
   that splits the four destination panels (Plans, Issues, Branches,
   Worktrees) into separate tabs and promotes Recent Activity to a
   **persistent strip above the tablist** — Activity is signal, not
   destination, and should remain ambient.

Panel rendering, polling cadence (2s `setTimeout`-recursion), drag-and-drop
mechanics, modal flow, fingerprint-suppressed diff, and the `/api/state`
shape are all unchanged. Each render function continues to write to the
same slot element it writes to today.

### Design decisions baked in from UI design agent review

The /draft-plan Phase 1 UI design agent recommended (and the adversarial
review accepted) a structure that overrides the issue body's first-pass
4-tab proposal:

| Issue body proposal | UI agent recommendation | Plan adopts |
|---|---|---|
| OVERVIEW tab (Recent Activity) as default-visible | Persistent strip above tablist, always visible, capped at 5 rows with internal scroll | Persistent strip |
| ETC tab combining Worktrees + Branches | Split: separate BRANCHES and WORKTREES tabs (orthogonal: refs vs filesystem) | Split |
| OVERVIEW first as landing tab | PLANS default (primary work surface); strip serves "what just happened" globally | PLANS default |
| Pill / underline / strip not specified | 2px bottom underline in `var(--accent)` matching `.panel-title` motif | Underline |
| Mobile collapse behavior not specified | Horizontal-scroll tablist below 700px with `scroll-snap-type: x proximity` | Scroll strip |
| Tab-state persistence "out of scope" | Include URL-hash now (~20 lines, shareable links + reload survival) | Include |

The corresponding issue-body AC "Dashboard loads with OVERVIEW tab active
by default (showing the Recent Activity panel)" is REFRAMED in this plan as
"Dashboard loads with PLANS tab active by default AND the Recent Activity
strip visible above the tablist." The underlying invariant — *default-visible
view contains the primary-attention content surface* — is preserved.

### Tab structure (final)

```
.topbar
  └── h1 "Z Skills Dashboard"
  └── #updated-at
#conn-banner (global)
#errors-banner (global)
#activity-strip (global, persistent)
  ├── .strip-title "Recent"
  └── #activity-body  ← renderActivity continues to write here
.tablist [role=tablist, aria-label="Dashboard sections"]
  ├── [role=tab, id=tab-plans,      aria-controls=plans,      aria-selected=true,  tabindex=0]  Plans
  ├── [role=tab, id=tab-issues,     aria-controls=issues,     aria-selected=false, tabindex=-1] Issues
  ├── [role=tab, id=tab-branches,   aria-controls=branches,   aria-selected=false, tabindex=-1] Branches
  └── [role=tab, id=tab-worktrees,  aria-controls=worktrees,  aria-selected=false, tabindex=-1] Worktrees
#tabpanels
  ├── #plans     [role=tabpanel, aria-labelledby=tab-plans,     tabindex=0]         contains <section class="panel panel-plans">
  ├── #issues    [role=tabpanel, aria-labelledby=tab-issues,    tabindex=0, hidden] contains <section class="panel panel-issues">
  ├── #branches  [role=tabpanel, aria-labelledby=tab-branches,  tabindex=0, hidden] contains <section class="panel panel-branches">
  └── #worktrees [role=tabpanel, aria-labelledby=tab-worktrees, tabindex=0, hidden] contains <section class="panel panel-worktrees">
#modal-root (global, z-index 50)
```

URL hash → active-tab slug mapping:
`#plans` ↔ Plans, `#issues` ↔ Issues, `#branches` ↔ Branches,
`#worktrees` ↔ Worktrees. Unknown / empty hash defaults to `#plans`.

### Skill version bump procedure (per phase)

After every phase's content edits and BEFORE staging the commit:

```bash
today=$(TZ=America/New_York date +%Y.%m.%d)
hash=$(bash scripts/skill-content-hash.sh skills/zskills-dashboard)
bash scripts/frontmatter-set.sh skills/zskills-dashboard/SKILL.md metadata.version "${today}+${hash}"
bash scripts/mirror-skill.sh zskills-dashboard
diff -rq skills/zskills-dashboard/ .claude/skills/zskills-dashboard/   # must be empty
git add skills/zskills-dashboard/ .claude/skills/zskills-dashboard/
```

The hash projection excludes the redacted `metadata.version` line itself,
so bumping the version does NOT cause the hash to change recursively
(verified in `scripts/skill-content-hash.sh` header). The bump is required
even when only static files change because the canonical projection
includes every regular file under the skill dir.

## Phase 3 — Tab behavior (JS + URL hash + keyboard nav)

### Goal

Wire up tab switching: click handler, keyboard arrow/Home/End navigation
with roving tabindex, automatic activation (focus = activate),
`aria-selected` and `tabindex` management, `hidden` flip on tabpanels, and
URL-hash routing via `hashchange` + `history.replaceState`. No changes to
poll plumbing, fingerprint diff, or render functions.

### Work Items

- [ ] **app.js — add a `Tabs` module-scope block** near the existing
  `boot()` and module-scope state (around lines 120-130 / 1694-1699). The
  code must use `textContent` / DOM APIs only — no `innerHTML`. Suggested
  shape (specific to this codebase):

  ```js
  // ─── Tab navigation (WCAG APG tabs pattern, automatic activation) ───
  const TAB_SLUGS = ["plans", "issues", "branches", "worktrees"];

  function readTabFromHash() {
    const h = (location.hash || "").replace(/^#/, "");
    return TAB_SLUGS.includes(h) ? h : "plans";
  }

  function setActiveTab(slug, { pushHash = true, focus = false } = {}) {
    if (!TAB_SLUGS.includes(slug)) slug = "plans";
    for (const s of TAB_SLUGS) {
      const tab = document.getElementById("tab-" + s);
      const panel = document.getElementById(s);
      if (!tab || !panel) continue;
      const isActive = (s === slug);
      tab.setAttribute("aria-selected", isActive ? "true" : "false");
      tab.tabIndex = isActive ? 0 : -1;
      if (isActive) {
        panel.removeAttribute("hidden");
      } else {
        panel.setAttribute("hidden", "");
      }
    }
    if (focus) {
      const activeTab = document.getElementById("tab-" + slug);
      if (activeTab) activeTab.focus();
    }
    if (pushHash && location.hash !== "#" + slug) {
      history.replaceState(null, "", "#" + slug);
    }
  }

  function bindTabEvents() {
    const tablist = document.querySelector('[role="tablist"]');
    if (!tablist) return;
    // Click handler
    tablist.addEventListener("click", (ev) => {
      const btn = ev.target.closest('[role="tab"]');
      if (!btn) return;
      const slug = btn.getAttribute("aria-controls");
      if (slug) setActiveTab(slug, { focus: true });
    });
    // Keyboard handler — Left/Right wrap, Home/End jump, automatic activation
    tablist.addEventListener("keydown", (ev) => {
      const btn = ev.target.closest('[role="tab"]');
      if (!btn) return;
      const slug = btn.getAttribute("aria-controls");
      const i = TAB_SLUGS.indexOf(slug);
      if (i < 0) return;
      let nextI = i;
      switch (ev.key) {
        case "ArrowLeft":  nextI = (i - 1 + TAB_SLUGS.length) % TAB_SLUGS.length; break;
        case "ArrowRight": nextI = (i + 1) % TAB_SLUGS.length;                    break;
        case "Home":       nextI = 0;                                             break;
        case "End":        nextI = TAB_SLUGS.length - 1;                          break;
        default: return;
      }
      ev.preventDefault();
      setActiveTab(TAB_SLUGS[nextI], { focus: true });
    });
    // hashchange (browser back/forward, or external link)
    window.addEventListener("hashchange", () => {
      setActiveTab(readTabFromHash(), { pushHash: false });
    });
  ```

### Design & Constraints

- **Automatic activation** (focus = activate) is appropriate per WCAG APG
  for this dashboard because: (a) all tabpanels render every 2s
  regardless of visibility (fingerprint-suppressed when data unchanged),
  so there's no expensive load to defer; (b) the switch is a CSS
  visibility flip with no perf cost.
- **Roving tabindex**: only the active tab has `tabindex="0"`; all
  inactive tabs have `tabindex="-1"`. The browser's natural Tab key
  navigation skips inactive tabs (it lands on the active tab), and
  arrow keys within the tablist handle within-tablist movement. After
  Tab leaves the tablist, focus moves into the active tabpanel
  (`tabindex="0"` on each panel).
- **`history.replaceState` not `pushState`** — tab switches should not
  pollute the back-stack with one entry per click. Reload-survival is
  the goal; navigation history is not.
- **`hashchange` listener is read-only** — when it fires (e.g., from
  external link or back/forward), call `setActiveTab(slug, { pushHash:
  false })` to avoid re-firing the listener via the same call's
  `replaceState`.
- **Polling untouched**: tab switching is DOM-only. The 2s poll loop
  continues to render into all five slot elements (Plans, Issues,
  Branches, Worktrees, Activity). Hidden tabpanels still receive DOM
  writes; the browser does not paint them but JS work proceeds normally,
  and `fingerprintPlans`-style diff suppression keeps the work cheap.
- **Enter / Space on a focused tab** is not specifically handled in the
  switch statement. This is intentional: (a) under automatic activation,
  focus already activated the tab, so Enter/Space are redundant for
  activation; (b) the tab is a `<button type="button">`, so the browser
  natively converts Space-press into a click event, which the existing
  click handler captures; (c) roving tabindex (only active tab has
  `tabindex="0"`) means Enter/Space on an inactive tab via Tab-key entry
  is impossible — the only way to focus an inactive tab is via arrow-key
  movement, which automatically activates it. Skipping explicit Enter/Space
  handling is correct under this design.
- **Tab key behavior after the tablist** is governed by natural DOM
  order. Because the active tabpanel itself has `tabindex="0"` (e.g.,
  `#plans`), Tab from the active tab `#tab-plans` lands FIRST on the
  tabpanel container (`#plans`), and a second Tab advances to the next
  focusable descendant — for Plans, that's `#dm-phase` (the
  Phase-by-phase segment button at index.html:35); for Issues /
  Branches / Worktrees, the first card with `tabindex="0"` rendered by
  `renderIssues` / `renderBranches` / `renderWorktrees`. The
  `tabindex="0"` on the tabpanel container is by design — it gives a
  focus target when the panel is empty AND it lets screen-reader users
  read the panel as a whole before drilling into its content. Phase 4's
  keyboard test accepts EITHER state (focus on tabpanel OR on a
  descendant) since both are WAI-ARIA APG-compliant.
