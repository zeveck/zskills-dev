# Plan: Shared preamble worktree gate for file-writing skills

> **Landing mode: PR** -- This plan targets PR-based landing. All phases
> use worktree isolation with a named feature branch.

## Overview

Six file-writing skills (`/draft-plan`, `/refine-plan`, `/draft-tests`,
`/add-block`, `/add-example`, `/fix-issues` sync) currently rely on the
caller to be in a worktree before they run, leaving dirty-main incidents
whenever the orchestrator forgets and the project has
`execution.main_protected: true`. This plan introduces a shared
`ensure-worktree.sh` helper under `skills/create-worktree/scripts/`
(matching the `sanitize-pipeline-id.sh` precedent) and threads a uniform
preamble through all six adopters. Closes #226 (plan-family / block-diagram
file-write surface) and #233 (`/fix-issues` SPRINT_REPORT.md commit).

### Design & Constraints

**Helper location.** Source: `skills/create-worktree/scripts/ensure-worktree.sh`.
Mirror: `.claude/skills/create-worktree/scripts/ensure-worktree.sh`
(regenerated by `bash scripts/mirror-skill.sh create-worktree`). Do NOT
hand-edit the mirror.

**API contract (document in script header comment, verbatim).**
- stdin: none
- stdout: exactly one line — worktree path (non-empty) OR empty string (no-op)
- stderr: progress/error messages
- exit 0: success (worktree created OR no-op)
- exit 2: `--worktree-override` validation failed
- exit 5: input validation (bad flag, missing required, not in git repo)
- exit 11: install-integrity (peer `create-worktree.sh` missing/not exec)
- exit N (N in {1, 3, 4, 6, 7, 8, 9, 10}): propagated verbatim from
  `create-worktree.sh`

**Exit-code separation + reservation (DA-15 / DA-R2-4).**
create-worktree.sh uses 5 for input-validation; the helper uses **11**
for install-integrity (peer missing). Helper's own input-validation
reuses 5 (same actionable category). 11 signals "re-mirror zskills".
Both headers carry the reserved-range comment (WI 1.9).

**Argument parser shape.** Bash regex flag loop matching
`create-worktree.sh:87-145`. `--slug` may be positional. `--prefix` and
`--pipeline-id` required; `--worktree-override`, `--purpose`,
`--allow-resume` optional. Unknown flag → stderr + exit 5.

**`--allow-resume` is opt-in (R-F7).** Plan-family opts in (re-entering
same slug is intentional). Block-diagram + /fix-issues do not (one-shot).

**Config reader (no jq, scoped to `execution`):**

```bash
PROJECT_ROOT=$(cd "$(git rev-parse --git-common-dir)/.." && pwd)
CONFIG_FILE="$PROJECT_ROOT/.claude/zskills-config.json"
LANDING="cherry-pick"  # default if unset
MAIN_PROTECTED="false"
if [ -f "$CONFIG_FILE" ]; then
  CONFIG_CONTENT=$(cat "$CONFIG_FILE")
  # Scoped to execution object (avoid top-level "landing" false-matches).
  if [[ "$CONFIG_CONTENT" =~ \"execution\"[[:space:]]*:[[:space:]]*\{[^}]*\"landing\"[[:space:]]*:[[:space:]]*\"([^\"]*)\" ]]; then
    LANDING="${BASH_REMATCH[1]}"
  fi
  # Accept both bare-boolean and string-quoted forms (DA-6 robustness).
  if [[ "$CONFIG_CONTENT" =~ \"execution\"[[:space:]]*:[[:space:]]*\{[^}]*\"main_protected\"[[:space:]]*:[[:space:]]*\"?(true|false)\"? ]]; then
    MAIN_PROTECTED="${BASH_REMATCH[1]}"
  fi
fi
```

**Schema-fragility caveat (DA-R2-10).** The `[^}]*` lookahead is non-greedy
on `}`. Today's `execution` block is flat; adding a nested object BEFORE
`main_protected` would terminate the match early. Same caveat applies to
`block-unsafe-project.sh.template:476`. Documented; acceptable trade-off
vs. extending `zskills-resolve-config.sh`'s contract (R-F12).

**In-worktree detection (verbatim, inside the helper):**

```bash
MAIN_ROOT=$(cd "$(git rev-parse --git-common-dir)/.." && pwd)
TOPLEVEL=$(git rev-parse --show-toplevel)
```

**Override validation (verbatim, symlink-resolved per DA-7):**

```bash
if [ -n "$WORKTREE_OVERRIDE" ]; then
  [ -d "$WORKTREE_OVERRIDE" ] || { echo "ensure-worktree: --worktree-override path does not exist or is not a directory: $WORKTREE_OVERRIDE" >&2; exit 2; }
  OVERRIDE_ABS=$(cd "$WORKTREE_OVERRIDE" && pwd)  # symlink-resolve
  OVERRIDE_COMMON=$(git -C "$OVERRIDE_ABS" rev-parse --git-common-dir 2>/dev/null) || { echo "ensure-worktree: --worktree-override is not a git repo: $WORKTREE_OVERRIDE" >&2; exit 2; }
  OVERRIDE_COMMON_ABS=$(cd "$OVERRIDE_ABS/$OVERRIDE_COMMON" && pwd)
  MAIN_COMMON_ABS=$(cd "$(git rev-parse --git-common-dir)" && pwd)
  [ "$OVERRIDE_COMMON_ABS" = "$MAIN_COMMON_ABS" ] || { echo "ensure-worktree: --worktree-override belongs to a different repo" >&2; exit 2; }
  [ "$OVERRIDE_ABS" != "$MAIN_ROOT" ] || { echo "ensure-worktree: --worktree-override cannot be MAIN_ROOT itself" >&2; exit 2; }
  printf '%s\n' "$OVERRIDE_ABS"
  exit 0
fi
```

**Gate logic precedence (after override returns).** Order is explicit:

1. **(0)** `--worktree-override` shortcut (above) — wins if provided.
2. **(1) In-worktree no-op.** If `MAIN_ROOT != TOPLEVEL`: emit a stderr
   informational note (`ensure-worktree: caller already in worktree at
   <TOPLEVEL>; proceeding`) so sibling-worktree drift is observable
   (DA-R2-17), then `printf '\n'`, exit 0. (Caller is already isolated;
   helper does not nest worktrees.)
3. **(2) main_protected gate (R-F8 + DA-17 fix).** If `MAIN_PROTECTED !=
   "true"`: `printf '\n'`, exit 0. **No `landing != "pr"` check** —
   `block-unsafe-project.sh.template:476` (the hook this preamble
   front-runs) gates purely on `main_protected`, so the helper aligns with
   the hook. `landing: direct + main_protected: true` is a config error
   already caught by `/run-plan` validation (`run-plan/SKILL.md:113-120`);
   the helper does not duplicate that check.
4. **(3) Dispatch.** Call `create-worktree.sh` per the block below.

**Create-worktree dispatch (verbatim):**

```bash
SCRIPT_DIR=$(cd "$(dirname "$0")" && pwd)
# --allow-resume only when caller opted in
RESUME_ARG=()
[ "$ALLOW_RESUME" = "1" ] && RESUME_ARG=(--allow-resume)
WT=$(bash "$SCRIPT_DIR/create-worktree.sh" \
  --prefix "$PREFIX" \
  --pipeline-id "$PIPELINE_ID" \
  ${PURPOSE:+--purpose "$PURPOSE"} \
  "${RESUME_ARG[@]}" \
  "$SLUG")
RC=$?
if [ "$RC" -ne 0 ]; then
  # Propagate exit code verbatim (no remap; preserves surface-bugs discipline).
  exit "$RC"
fi
printf '%s\n' "$WT"
```

**Up-front validation (exit 5 on failure):** `git rev-parse
--git-common-dir` resolves; `--prefix` non-empty; `--pipeline-id`
non-empty; `--slug` flag OR exactly one positional remains after parsing.

**Tracking-marker discipline (DA-20).** Helper writes no markers; only
dispatched create-worktree.sh writes `.zskills-tracked`. No-op paths
inherit parent's marker or create no worktree.

**Consumer propagation (DA-R2-13 + DA-R3-2).** Downstream `/update-zskills`
Step 3 of Pull Latest path (`skills/update-zskills/SKILL.md:1667-1673`)
re-copies changed skills; metadata.version bump (WI 1.11) triggers the
diff. Helper lives under `skills/create-worktree/` (core manifest), so
all consumers — including those without `--with-block-diagram-addons` —
receive it. The Step 3 prose says "copy the new version"; this MUST be
implemented as a recursive directory copy (`cp -a src/. dst/` semantics),
not a per-file diff-and-update — a per-file-diff implementation would
silently skip the brand-new `ensure-worktree.sh` because it does not
exist at the destination. A caller-side fallback (Phase 2/3/4 preambles)
re-emits the exit-11 message when the helper itself is missing at the
expected mirror path, giving consumers an actionable error rather than
bash's generic `No such file or directory`.

**Out-of-scope edges.** Worktree-on-main (`git worktree add ... main`)
— helper no-ops; auto-commit fence runs (TOPLEVEL != MAIN_ROOT) but
the `git commit` is gated by the `block-unsafe-project.sh.template:476`
backstop (`is_main_protected && is_on_main` fires on commit, per DA-R2-9
audit). No `.landed` writes (`/commit land`'s job). No `git push`.

### Design & Constraints

**Runtime-path-resolution semantics (R3-1 / R3-5).** `zskills-paths.sh`
resolves the project root via the env-var override
`ZSKILLS_PATHS_ROOT`, falling back to `$CLAUDE_PROJECT_DIR` (which
ALWAYS points to MAIN even after the preamble's `cd`, per
`run-plan/SKILL.md:254,332,431`). The script's own docstring
(`zskills-paths.sh:9-11`) documents the PR-mode override pattern verbatim:
`ZSKILLS_PATHS_ROOT="$WORKTREE_PATH"`. The preamble MUST export this
variable after `cd "$WT_PATH"`, otherwise downstream `$ZSKILLS_PLANS_DIR`
/ `$ZSKILLS_AUDIT_DIR` / `$ZSKILLS_ISSUES_DIR` resolutions (in argument
parsing AND in the auto-commit fence) would anchor on MAIN, producing
absolute paths like `/<main-repo>/plans/FEATURE.md` that the auto-commit
fence's out-of-tree guard rejects with exit 1 — strictly worse than the
pre-plan outcome.

**Preamble invocation template (verbatim, parameterize per skill).**
Includes ENFORCED `cd "$WT_PATH"` (R2-F7), helper-missing fallback
(DA-R3-2), AND `export ZSKILLS_PATHS_ROOT="$WT_PATH"` (R3-1 fix):

```bash
MAIN_ROOT=$(cd "$(git rev-parse --git-common-dir)/.." && pwd)
TOPLEVEL=$(git rev-parse --show-toplevel)
HELPER="$CLAUDE_PROJECT_DIR/.claude/skills/create-worktree/scripts/ensure-worktree.sh"
# Caller-side install-integrity fallback (DA-R3-2): if /update-zskills
# Step 3 ran as per-file-diff and skipped the new file, the helper itself
# is missing. Emit an actionable exit-11 message instead of bash's
# `No such file or directory`.
if [ ! -x "$HELPER" ]; then
  echo "<skill>: ensure-worktree.sh missing at $HELPER — run /update-zskills to repair" >&2
  exit 11
fi
WT_PATH=$(bash "$HELPER" \
  --prefix <prefix> \
  --pipeline-id "<skill>.${TRACKING_ID}" \
  --allow-resume \
  --purpose "<skill> auto-worktree; <context>" \
  "${TRACKING_ID}")
RC=$?
if [ "$RC" -ne 0 ]; then
  echo "ensure-worktree failed (rc=$RC) for /<skill>" >&2
  # rc=3 (poisoned branch): suggest `/create-worktree resume <slug>` or
  # delete the poisoned branch. rc=11: helper install-integrity — run
  # `/update-zskills` to repair. Other codes: see helper script header.
  exit "$RC"
fi
if [ -n "$WT_PATH" ]; then
  cd "$WT_PATH" || { echo "<skill>: cd $WT_PATH failed" >&2; exit 1; }
  # R3-1 path-resolution fix: re-anchor zskills-paths.sh under the
  # worktree so subsequent $ZSKILLS_PLANS_DIR / $ZSKILLS_AUDIT_DIR /
  # $ZSKILLS_ISSUES_DIR resolutions land in WT, not main. Export (not
  # just set) so child shells / re-sourcing inherits it.
  export ZSKILLS_PATHS_ROOT="$WT_PATH"
fi
# Empty $WT_PATH means no worktree was created (caller already in one OR
# main not protected); proceed in cwd. $ZSKILLS_PATHS_ROOT stays unset
# in that case, so paths fall back to $CLAUDE_PROJECT_DIR as before.
```

**Self-contained auto-commit step (verbatim, plan-family skills).** Each
skill defines its OWN file variable name (`$OUTPUT_FILE` for /draft-plan,
`$PLAN_FILE` for /refine-plan and /draft-tests). The fence re-derives
everything it needs locally, re-sources `zskills-paths.sh` so paths
re-anchor (R3-1), remaps MAIN-rooted `$FILE_VAR` values to WT-rooted
ones (R3-1 dataflow), and uses the portable realpath pattern adapted
from `hooks/warn-config-drift.sh:181-203` (DA-R2-1: BSD/macOS realpath
lacks `--relative-to`; R3-6: "adapted from", not byte-equivalent):

```bash
# Self-contained; belt-and-suspenders cd in case WT_PATH was set above.
[ -n "${WT_PATH:-}" ] && cd "$WT_PATH" 2>/dev/null || true
MAIN_ROOT=$(cd "$(git rev-parse --git-common-dir)/.." && pwd)
TOPLEVEL=$(git rev-parse --show-toplevel)
if [ "$TOPLEVEL" != "$MAIN_ROOT" ]; then
  # Re-source path-config under the worktree root so $ZSKILLS_PLANS_DIR
  # etc resolve to TOPLEVEL/... rather than $CLAUDE_PROJECT_DIR/... — R3-1.
  # Belt-and-suspenders: the preamble already exported this, but the
  # fence re-exports in case the preamble code path was bypassed
  # (e.g., caller-in-worktree, where WT_PATH was empty but TOPLEVEL is
  # already a worktree — we want paths anchored on TOPLEVEL).
  export ZSKILLS_PATHS_ROOT="$TOPLEVEL"
  . "$CLAUDE_PROJECT_DIR/.claude/skills/update-zskills/scripts/zskills-paths.sh"

  # R3-1 path-remap: if $FILE_VAR was computed BEFORE the preamble set
  # $ZSKILLS_PATHS_ROOT (e.g., a stale value cached in the caller's
  # argument-resolution block), it may still be MAIN-anchored. Re-anchor
  # to TOPLEVEL. This is the load-bearing remap.
  case "$FILE_VAR" in
    "$MAIN_ROOT"/*) FILE_VAR="$TOPLEVEL/${FILE_VAR#"$MAIN_ROOT/"}" ;;
  esac

  # Portable FILE_REL (DA-R2-1, R3-6: adapted from warn-config-drift.sh:181-203).
  FILE_REL=""
  if FILE_REL=$(realpath --relative-to="$TOPLEVEL" "$FILE_VAR" 2>/dev/null) \
       && [ -n "$FILE_REL" ]; then
    case "$FILE_REL" in /*) FILE_REL="" ;; esac
  fi
  if [ -z "$FILE_REL" ]; then
    ABS_FILE=$(cd "$(dirname "$FILE_VAR")" 2>/dev/null && pwd)/$(basename "$FILE_VAR")
    case "$ABS_FILE" in
      "$TOPLEVEL"/*) FILE_REL="${ABS_FILE#"$TOPLEVEL"/}" ;;
      *) echo "<skill>: cannot normalize $FILE_VAR vs $TOPLEVEL" >&2; exit 1 ;;
    esac
  fi
  # Out-of-tree guard (DA-R2-5). After the path-remap above, FILE_REL
  # should never be `../*` for legitimate inputs; if it is, fail loud
  # (something is wrong with the caller's resolution).
  case "$FILE_REL" in
    /*|../*) echo "<skill>: $FILE_VAR is outside worktree $TOPLEVEL" >&2; exit 1 ;;
  esac

  git -C "$TOPLEVEL" add "$FILE_REL"
  STAGED=$(git -C "$TOPLEVEL" diff --cached --name-only)
  if [ "$STAGED" != "$FILE_REL" ]; then
    echo "<skill>: unexpected staged set: $STAGED (expected $FILE_REL only)" >&2
    exit 1
  fi
  . "$CLAUDE_PROJECT_DIR/.claude/skills/update-zskills/scripts/zskills-resolve-config.sh"

  # Per-skill commit subject (R2-F8: case-stmt, not table cell).
  BASE=$(basename "$FILE_REL" .md)
  case "<skill>" in
    draft-plan)  COMMIT_MSG_SUBJECT="docs(plans): draft $BASE" ;;
    refine-plan) COMMIT_MSG_SUBJECT="docs(plans): refine $BASE" ;;
    draft-tests) COMMIT_MSG_SUBJECT="docs(tests): draft test specs for $BASE" ;;
  esac

  if [ -n "$COMMIT_CO_AUTHOR" ]; then
    git -C "$TOPLEVEL" commit --trailer "Co-Authored-By: $COMMIT_CO_AUTHOR" -m "$COMMIT_MSG_SUBJECT"
  else
    git -C "$TOPLEVEL" commit -m "$COMMIT_MSG_SUBJECT"
  fi
fi
```

**R3-1 dataflow** (why the path-remap is necessary and sufficient).
At skill entry: `$CLAUDE_PROJECT_DIR=$MAIN_ROOT`. Skill arg-parsing
sources `zskills-paths.sh` BEFORE the preamble runs, computing
`$OUTPUT_FILE=$MAIN_ROOT/plans/X.md` (for /draft-plan) or `$PLAN_FILE`
similarly. The preamble then creates a worktree and exports
`ZSKILLS_PATHS_ROOT=$WT_PATH`, but the already-computed `$OUTPUT_FILE` /
`$PLAN_FILE` are still MAIN-anchored strings. The skill body writes its
file content to `$OUTPUT_FILE` AFTER cd-ing into the worktree — but the
write target string is absolute, so it lands in MAIN regardless. Two
mitigations together close the gap:
1. **Re-source `zskills-paths.sh` with `ZSKILLS_PATHS_ROOT` set** before
   any post-preamble path read. The plan-family skills already
   re-source it in the auto-commit fence (R2-F9 / R2-14); now the
   re-source happens under the WT-rooted override.
2. **Path-remap `$FILE_VAR`** explicitly: if it starts with `$MAIN_ROOT/`,
   substitute `$TOPLEVEL/`. This handles the case where the skill body
   computed `$OUTPUT_FILE` before the preamble fired and cached it.

The skill body MUST ALSO recompute `$OUTPUT_FILE` after the preamble
exports `ZSKILLS_PATHS_ROOT` — OR ensure the only consumer of the
MAIN-rooted value is the auto-commit fence (which the remap fixes). For
the three plan-family skills, the file-write step (which writes the plan
body to disk) MUST run AFTER the preamble's `export` so the path it
computes is WT-rooted. WI 2.1/2.3/2.5 already insert the preamble BEFORE
`## Arguments`, where `$OUTPUT_FILE` is computed — so the natural skill
flow gets WT-rooted paths. The auto-commit remap is a backstop for
defensive layering.

**Portable-realpath pattern provenance (R3-6).** The pattern is **adapted
